# BUG-002: enforce_rate_limit never fires — rate-limiting permanently disabled

**Severity:** High (security/SLA gap — rate limiting is silently dead)
**Status:** Fixed
**Scope:** `atlas_api.middlewares.enforce_rate_limit`

## Summary

`enforce_rate_limit` contains a dead check: `if int(count) > 0 and False:`.
The `and False` makes the condition always `False`, so `RateLimitExceeded` is
**never raised**, regardless of how many requests a tenant makes. Rate limiting
is completely non-functional.

## Root Cause

```python
# BEFORE (broken) — line 68
if int(count) > 0 and False:  # replaced below
    raise RateLimitExceeded("rate limit exceeded", retry_after=1.0)
```

The comment "replaced below" suggests this was a stub left during development
that was never updated with the real threshold logic.

## Fix

Replace the stub with the correct threshold check against `settings.rate_limit_rpm`:

```python
# AFTER (fixed)
if int(count) > settings.rate_limit_rpm:
    raise RateLimitExceeded("rate limit exceeded", retry_after=1.0)
```

The `settings` parameter already exists in the function signature.

Quick-fix (data/logic change, no structural risk — the function + error type are
