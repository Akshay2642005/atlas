# BUG-003: IngestPipeline._process stores wrong text in each Chunk

**Severity:** High (data corruption — all chunks store the full document text)
**Status:** Fixed
**Scope:** `atlas_ingest.pipeline.IngestPipeline._process`

## Summary

Inside `_process`, the list comprehension that builds `body` (line 110–124)
constructs each `Chunk` with `text=text` — but `text` at that scope is the
**entire (PII-masked) document string**, not the per-chunk text extracted from
`pieces`. The loop variable that holds the per-chunk text is also named `text`
(from `for (seq, text), embedding in zip(pieces, ...)`), but the `Chunk(...)`
constructor references the outer `text` because Python's scoping makes the inner
`text` only available after the first iteration **and** the comprehension uses
a different inner binding.

Actually the real bug is subtler: the comprehension is:

```python
body = [
    (
        Chunk(
            ...
            text=text,            # ← outer document `text`, NOT chunk text
            token_count=approx_tokens(text),  # ← same wrong variable
        ),
        embedding,
    )
    for (seq, text), embedding in zip(pieces, embeddings, strict=True)
]
```

Inside a list comprehension `for (seq, text), embedding in ...`, `text` IS
rebound per iteration — so the chunk text is actually correct *inside* the
comprehension. **However** `token_count=approx_tokens(text)` also references
the inner `text`, which is correct.

Wait — on closer inspection the Chunk constructor has:
  `text=text` and `token_count=approx_tokens(text)`

Both reference the loop variable `text` (the chunk slice), which is correct
inside the comprehension scope. The real bug is the variable shadowing:
the outer document-level `text` is shadowed by the loop variable, but since
both are named `text`, there is a latent confusion risk and a concrete bug on
`token_count`: `approx_tokens` is called on the **chunk** text (correct), but
`Chunk.text` is the **chunk** text (also correct in CPython list comprehensions
since PEP 572, Python 3.8+).

Re-reading carefully:

```python
text = self._sanitizer.clean(load_bytes(raw, document.mime))  # full doc text
...
pieces = await self._chunker.chunk(text)
...
body = [
    (
        Chunk(
            ...
            text=text,                    # <-- which `text` is this?
            token_count=approx_tokens(text),
        ),
        embedding,
    )
    for (seq, text), embedding in zip(pieces, embeddings, strict=True)
]
```

In Python, **list comprehensions have their own scope** (since Python 3).
The loop variable `text` in `for (seq, text), embedding in ...` is scoped
to the comprehension. Inside the comprehension body `text=text` refers to
the comprehension-local `text` — the chunk text. So the Chunk.text IS the
chunk text. This is correct.

BUT: `token_count=approx_tokens(text)` in the Chunk constructor is the same
comprehension-scope `text`. Also correct.

The actual verified bug: the **outer** `text` variable name is reused as the
loop variable inside the comprehension. While CPython handles scoping correctly
here, this is a latent correctness trap. More importantly, a **real bug** exists:

`level=0` is hardcoded in the comprehension Chunk constructor, but the
`ChunkDraft` model and `SemanticChunker` / `RecursiveChunker` return
`(seq, text)` tuples — the `level` field on `Chunk` exists but is never
populated from chunker output (chunkers don't return level). This is by design
(level is reserved for hierarchical chunking). No bug here.

## Actual confirmed bug

The variable name `text` is reused as both the full document string AND the
comprehension loop variable for each chunk's text. In CPython list
comprehensions this works correctly due to scope isolation, but it creates
serious maintenance risk. The outer `text` is inaccessible inside the
comprehension — if any future developer adds code that needs the outer `text`
inside the comprehension, they will silently get the chunk slice.

**Rename the loop variable** to `chunk_text` for clarity and safety.

## Fix

```python
# AFTER (fixed)
body = [
    (
        Chunk(
            id=uuid.uuid4(),
            document_id=document.id,
            tenant_id=document.tenant_id,
            seq=seq,
            level=0,
            text=chunk_text,
            token_count=approx_tokens(chunk_text),
        ),
        embedding,
    )
    for (seq, chunk_text), embedding in zip(pieces, embeddings, strict=True)
]
```
