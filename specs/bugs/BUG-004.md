# BUG-004: ChatPort.stream declared as plain def, not async def

**Severity:** Medium (protocol mismatch — type-unsafe, runtime error if called via port)
**Status:** Fixed
**Scope:** `atlas_core.domain.ports.ChatPort`

## Summary

`ChatPort.stream` is declared as a plain synchronous `def`:

```python
def stream(self, messages: Sequence[ChatMessage], *, max_tokens: int | None = None) -> AsyncIterator[str]: ...
```

The concrete implementation `GroqChat.stream` is an `async def` (async
generator). The Port (Protocol) and the Adapter must match:
- A plain `def` returning `AsyncIterator[str]` is a sync function that happens
  to return an async iterable — callers would call it without `await` and get
  back the iterator.
- An `async def` generator function returns an `AsyncGenerator` (subtype of
  `AsyncIterator[str]`) and **must** be called without `await` but iterated
  with `async for`.

The mismatch means any code that calls `chat_port.stream(...)` via the Protocol
interface (not the concrete class) gets inconsistent behaviour depending on
which implementation is behind the port. It also causes mypy to silently accept
protocol violations.

## Fix

Change the Protocol method signature to `async def`:

```python
async def stream(
    self, messages: Sequence[ChatMessage], *, max_tokens: int | None = None
) -> AsyncIterator[str]: ...
```
