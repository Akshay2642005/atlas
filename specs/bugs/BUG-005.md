# BUG-005: run() constructs AtlasSettings() directly, bypassing load_settings() cache

**Severity:** Low (settings loaded twice at startup; env-var reads not shared)
**Status:** Fixed
**Scope:** `atlas_api.main.run`

## Summary

`run()` calls `AtlasSettings()` directly:

```python
def run() -> None:
    settings = AtlasSettings()
    uvicorn.run(app, host=settings.api.host, port=settings.api.port)
```

The project defines `load_settings()` with `@lru_cache(maxsize=1)` in
`atlas_core.config` as the canonical single-instance accessor for settings.
`create_app()` (and the DI container via `CoreProvider`) both use
`load_settings()`. Calling `AtlasSettings()` directly:

1. Creates a **second** settings object, doubling env-var parsing at startup.
2. If settings are mutated or monkey-patched in tests, `run()` will read a
   different object than the rest of the app.
3. Violates the project's DI-first principle.

## Fix

```python
def run() -> None:
    settings = load_settings()
    uvicorn.run(app, host=settings.api.host, port=settings.api.port)
```

Import `load_settings` (already imported in the module that calls it — just
update the call site).
