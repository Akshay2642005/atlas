# BUG-007: injection guard rejects documents containing "ecosystem:" or "Operating System ::"

**Severity:** Medium (legitimate documents are silently dropped at ingest)
**Status:** Fixed
**Scope:** `atlas_core.security.injection.HeuristicInjectionGuard`

## Summary

One of the guard's patterns was the bare substring:

```python
r"system\s*:\s*"
```

It was meant to catch chat role prefixes (`system: you are …`), but with no
anchoring it matches the word "system" followed by a colon *anywhere*, including
inside longer words.

## Impact

Ingesting the public documentation corpus (`make eval-ingest-docs`) rejected
4 of 925 documents, each with
`prompt-injection patterns detected in source content`:

| document | match |
| --- | --- |
| `django/docs/howto/static-files/deployment.txt` | `ecosystem: ` |
| `django/docs/internals/contributing/index.txt` | `ecosystem: ` |
| `django/docs/intro/whatsnext.txt` | `ecosystem: ` |
| `django/docs/intro/reusable-apps.txt` | `Operating System ::` |

The rejection is total: `IngestPipeline.run` raises, the harness logs `fail`,
and the whole document is skipped. A document mentioning its "ecosystem" is
unretrievable, and the only trace is a `fail` line in the ingest log.

## Root cause

A pattern intended to match a *line-leading chat role* was written as an
unanchored substring. `ecosystem:` contains `system:` starting at offset 2, and
`Operating System ::` matches `system` + whitespace + `:`.

## Fix

Anchor the pattern to the start of a line and allow only horizontal whitespace
before it, which is what a chat template role prefix looks like:

```python
r"(?m)^[ \t]*system[ \t]*:[ \t]*"
```

`MULTILINE` makes `^` match after every newline; `[ \t]*` rather than `\s*`
prevents the pattern from bridging blank lines.

## Verification

- `tests/test_security.py::test_injection_guard_ignores_the_word_system_mid_line`
  asserts that "vibrant ecosystem:" and `"Operating System :: OS Independent"`
  are clean.
- `tests/test_security.py::test_injection_guard_flags_a_line_initial_role_prefix`
  asserts that `\nsystem: …` and `  System : …` are still flagged.
- Re-ingesting the four rejected Django documents succeeds.

## Prevention

The residual false positive is a document with a line that *starts* with a
`system:` key (an indented YAML snippet, say). The guard is heuristic and fails
closed, so that document is still dropped. If that shows up in practice, the
guard should redact the matched span instead of rejecting the document — but a
substring match is not an acceptable substitute for anchoring.
