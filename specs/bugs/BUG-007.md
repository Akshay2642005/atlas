# BUG-007: injection guard rejects documents containing "ecosystem:" or "Operating System ::"

**Severity:** Medium (legitimate documents are silently dropped at ingest)
**Status:** Fixed
**Scope:** `atlas_core.security.injection.HeuristicInjectionGuard`

## Summary

One of the guard's patterns was the bare substring:

```python
r"system\s*:\s*"
```

It was meant to catch chat role prefixes (`system: you are …`), but with no
anchoring it matches the word "system" followed by a colon *anywhere*, including
inside longer words.

## Impact

Ingesting the public documentation corpus (`make eval-ingest-docs`) rejected
21 of 929 documents, every one of them with
`prompt-injection patterns detected in source content`:

| document | match |
| --- | --- |
| `django/docs/howto/static-files/deployment.txt` | `ecosystem: ` |
| `django/docs/internals/contributing/index.txt` | `ecosystem: ` |
| `django/docs/intro/whatsnext.txt` | `ecosystem: ` |
| `django/docs/intro/reusable-apps.txt` | `Operating System ::` |
| `django/docs/topics/db/queries.txt` | `system:` at a line start (wrapped prose) |
| …17 more Django reference/topic pages | same |

The rejection is total: `IngestPipeline._process` raises, the harness logs
`fail`, and the whole document is unretrievable. The only trace is a `fail`
line in the ingest log.

## Root cause

A pattern intended to match a *line-leading chat role* was written as an
unanchored substring.

- `ecosystem:` contains `system:` at offset 2.
- `Operating System ::` matches `system` + whitespace + `:`.
- Anchoring to the line start is not sufficient either: wrapped prose puts the
  word at a line start ("Django uses an intuitive\n`system:` A model class …").
  That version still rejected `django/docs/topics/db/queries.txt`.

## Fix

A chat role is a *block*: it starts the document or follows a blank line.

```python
r"(?m)(?:\A|\n[ \t]*\n)[ \t]*system[ \t]*:[ \t]*(?=\S)"
```

`\A` rather than `^` is load-bearing: with `MULTILINE`, `^` matches after every
newline and collapses the pattern back to line-anchoring. `[ \t]*` rather than
`\s*` prevents the pattern from bridging blank lines.

## Verification

- `tests/test_security.py::test_injection_guard_ignores_the_word_system_mid_line`
  asserts that "vibrant ecosystem:", `"Operating System :: OS Independent"`, and
  wrapped prose are clean.
- `tests/test_security.py::test_injection_guard_flags_a_role_prefix_block`
  asserts that a document-initial `system: …` and a blank-line-preceded
  `  System : …` are still flagged.
- All 929 corpus documents scan clean (0 flagged), and re-ingesting the 21
  rejected documents succeeded (775 chunks).

## Prevention

The guard is heuristic and fails closed, so a residual false positive — a
document with a line-initial `system:` key, e.g. an indented YAML snippet —
still drops the document. If that appears in practice, redact the matched span
instead of rejecting the document.

The real lesson is in [BUG-008](BUG-008.md): because the guard ran *after* the
document row was persisted, these false positives did not merely skip a file,
they made it unretrievable on every subsequent ingest.
